# 降级与容错方案（参考 wuu 三种降级哲学）

> 状态：P0 ✅ / P1 ✅ / P2 ✅（方案 4、6 已实施并验证；方案 5 无需改动）
> 参照：wuu 项目的降级哲学——**①链式回退（能替代就替代）②保留现场（不能替代就保持原状）③安全兜底（fail-closed）**，且所有降级**显式留痕**（用户知道当前处于降级状态）。
> 目标：把「外部依赖挂掉」从"整场对话失败"变成"降级后继续"，且降级可见、可查。

## 二、降级方案（按三种哲学组织）

### ① 链式回退（能替代就替代）

**方案 1：模型调用回退链**（最有价值，对齐 wuu 的 `ModelAliasFallback` 显式标记）

- **触发**：请求的模型调用失败（网络错误、5xx、超时；**4xx 鉴权/上下文溢出不触发**——那是配置问题不是故障）。
- **回退链**：请求模型 → 用户默认模型（`settings.default_model_id`）→ 平台默认（`DEFAULT_MODEL_ID`），沿链尝试，成功即用。
- **显式留痕**：`run.completed` 事件带 `fallback` 字段（`{from, to}`），前端可在回复里展示"已从 DeepSeek 降级到 MiniMax"。对齐 wuu「调用方和 UI 都能看到降级」。
- **改动点**：`agentrun/execution.py`（chat 的模型调用包一层回退逻辑）+ `agentstream/types.py`（Event 加字段）。

**方案 2：E2B 沙箱 → 纯文本降级**（本方案的第一步，改动最小）

- **触发**：`SandboxToolSet.execute()` 里 `workspace()` 连接/创建失败。
- **降级行为**：把 `workspace()` 移进 try/except，E2B 失败返回 `{"error": "sandbox unavailable: ..."}` 作为工具结果回传——Agent 感知后自动转纯文本回复，**对话不中断**。
- **改动点**：`sandbox/tools.py` execute() 一处。

**方案 3：COS 图片降级**

- **触发**：COS 未配置/读取失败。
- **降级行为**：图片输入降级为纯文本（丢弃图片 URL，向用户提示"图片暂不可用"），对话继续。
- **改动点**：`images/service.py` 的 message_image_urls 失败时返回空列表（而非 raise）。

### ② 保留现场（不能替代就保持原状）

**方案 4：会话摘要防死锁**（借鉴 wuu compact）✅ 已实施

- 当前：摘要失败退回全量历史 ✅。
- 增强（已实施）：摘要输出超长（>2000 字符）时用更严格压缩指令**重试 1 次**；摘要请求本身溢出时裁剪最旧一半消息重试（防「压缩→溢出→再压缩」死锁），最多 3 次。
- 改动点：`execution.py` summary_compress 的重试逻辑（`SUMMARY_MAX_RETRIES=3`、`SUMMARY_MAX_CHARS=2000`）；触发阈值 `HISTORY_THRESHOLD_RATIO=0.4`（对齐 Go 版）。

**方案 5：模型目录内嵌兜底**

- 现状：`catalog.py` 模型定义代码内嵌（天然内嵌兜底），无动态刷新，**无需改动**。保留即可。

### ③ 安全兜底（fail-closed）

**方案 6：凭据存储加固**（安全改进点）✅ 已实施

- 现状：用户 API key（`user_providers`）和 MCP header（`user_mcp_headers`）**明文存 SQLite**。
- 已实施：`userconfig/secret.py` 提供 XOR + Base64 混淆（`enc:v1:` 前缀），`providers.py`/`mcp.py` 写入时 `obfuscate()`、读取时 `deobfuscate()`；旧明文数据向后兼容（无前缀原样返回）。密钥来自环境变量 `EDITH_SECRET_KEY`，缺省回退内置 fallback key（防君子不防小人）。
- 注意：这是**安全兜底**的补强，不是功能降级。真正上多用户/云端前必须换成 KMS / 信封加密 / 专用密钥管理（`secret.py` docstring 已注明边界）。

### ④ 基础可靠性（对齐 wuu retry.go）

**方案 7：模型调用有限重试**

- **触发**：对「可重试错误」（网络、5xx、超时、不完整流）做有限重试（2 次，指数退避 + jitter）；对「不可重试」（4xx 鉴权、上下文溢出、无效请求）不重试。
- **改动点**：`execution.py` chat 的模型调用包一层重试装饰器。
- 与方案 1 的关系：重试失败后再走回退链。

## 四、与简历故事点的关联

把方案 2+1 落地后，可以讲一个完整的「故障预案」故事：

> **外部依赖故障时自动降级，且降级显式可见**——E2B 沙箱不可用时 Agent 自动转纯文本继续回答；模型服务异常时沿「请求模型→用户默认→平台默认」回退，并在回复中标记降级来源；所有降级都有日志（方向 1 的可观测性）可查。

这正好补齐之前「优雅降级只覆盖 Skills/Volumes」的短板，变成真正的架构亮点。
